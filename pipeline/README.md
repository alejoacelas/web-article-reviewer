# Pipeline harness

Code that the [edit design](../DESIGN.md) calls "the harness". The
[review-article skill](../skills/review-article/SKILL.md) is the procedure that runs one
article end to end.

- `prepare.py` — capture folder → `<run-dir>/bundle.json`: identity, article text,
  structural units, every external link occurrence (image embeds excluded) with its
  section, containing unit, sentence, and a live HEAD signal, and link batches (one
  call per leaf section, adjacent small sections coalesced, ≤25 targets per call).
- `split_units.py` — deterministic structural units (paragraph, list item, caption,
  table, heading, footnote) keyed by id and offsets, consumed by prompt 07 and, through
  `structural_unit_id` on each retained item, by prompt 10.
- `schemas/NN-*.schema.json` — the ten output schemas. Each carries only the judgment
  its stage adds; 01 and 03 grew out of the 27 August experiment schemas, with the
  passage-based unit and `editorial_escalation` verdict added.
- `run.workflow.js` — the Workflow (ultracode) script: 01 → parallel(02 batches, 03
  batches, 04, 07 batches) → 05 → 06 → 08 → 09 → 10. Opus 5 runs 01–04, 07, 09; Fable
  runs 05, 06, 08, 10. Stage agents read the prompt, article, inputs and schema from
  disk and save their JSON to `<run-dir>/stages/`; Haiku agents relay the two harness
  commands between stages; a `null` return is retried once under a new label. The
  `const S = {...}` schema block is generated by `build_workflow.py`.
- `harness.py` — `inputs <run> <stage>` writes the next stage's input files and batch
  list; `join <run> <stage>` validates required fields and enums, checks one entry per
  expected id, locates every quoted passage in the article (exact → smart-quote
  normalised → whitespace), records offsets and `structural_unit_id`, and writes
  `<run-dir>/joined/NN.json` with a `harness_summary`. Problems are recorded on the
  entry, never dropped. A merge verdict of `retained` or `conflict_recorded` counts as
  retained; `superseded` does not.
- `build_workflow.py <run-dir>` — regenerates the schema block and prints the Workflow
  `args` for a prepared run.
- `deliver.py <run-dir> --folder ID [--doc ID]` — Google Doc from the captured
  Markdown; minimal `gdoc suggest` per retained change (only the words that differ,
  widened until unique); plain `Problem / Why / Sources` comments anchored on text that
  survives acceptance, overflow continued as replies; `no_change`, `unverifiable`,
  pruned and rejected items as resolved comments. With `--doc` and an existing
  `delivery.json`, redoes only failed items.
- `build_review.py <run-dir> --doc-url URL` — `review.md`: the grade line, then every retained
  edit in place with its finding, verbatim reason, evidence, and run, then the not-retained
  and checked-no-change lists.

Run folders live in `../runs/<date>-<name>/<NN-wpid-slug>/` with `bundle.json`,
`inputs/`, `stages/`, `joined/`, `delivery.json`, `review.md`, and `workflow-args.json`.
